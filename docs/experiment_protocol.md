# 实验协议

## 搜索与验证

试验前固定模型版本、控制器、参数范围、seed、初态、target、时长、压力配置、冲量及评价口径，并建立唯一 campaign。`configs/campaigns/` 保存已执行实验的声明式计划。

每轮先记录选择参数的依据，再执行一次 trial，读取返回结果后选择下一点。固定条件下同一参数不重复搜索；固定种子重复仅用于复现检查，不视为独立样本。`fail=true` 或 `converged=false` 的点不进入最优候选集。

候选按同一搜索工况中最低有限 J 选择。验证场景在搜索前确定；进入验证后冻结参数，不替换失败场景。所有失败、未收敛和无改善点保留。停止原因记录为预算耗尽、无改善、目标达成或执行异常。

## 来源与对照

Agnes 搜索需保存逐轮理由、工具调用和实际返回。网格扫描由 `tools/scan.js` 执行，方法探索由 `tools/probe-stage-d2.js` 执行，两者单独标记。公开 selftest 参数属于已知先验。人工对照只有实际执行并记录耗时及参数后才纳入分析。

D2-T 是各控制器的独立搜索，预算上限12、最低6个搜索点、6个固定验证场景；实际搜索数在报告中分别列出。D2-M2 是固定6/0.02/16、相同初态和seed的四组控制器配对，不是自主参数搜索。

## 复现

`npm run verify:evidence` 校验 CSV 散列并复算指标、诊断和控制环统计。`npm run verify:history` 使用对应历史模拟器重现110条保存的采样序列，以及36个网格点和9个selftest样例。`npm run audit:sessions` 核对保存会话中的事件、effect配对、执行时长和runId覆盖。

模型、压力或评价条件不同的 J 分组呈现；同工况控制器比较需保持 gains、初态、seed 与评价口径一致。原D未收敛结果与后续D2结果分别保留。

## 实车验收

实车测试另行安排，需要现场人员、固定防护、可靠断电/急停方式、本车已验证参数和车端协议验收。不得直接套用仿真最佳参数。

首先验证串口接线、固件版本、Stop/Start与参数确认、设备侧心跳看门狗、遥测时序及中断清理；设备运行状态和实际参数无法读回时记为未知。当前串口主机工具不会据未知状态自动提升 last-good。

实车对照记录电池状态、地面、架空/落地条件及重复结果。手推冲量难以精确重复，应记录其方法并区别于仿真中可重复的角速度冲量。当前1–4秒 trial 不覆盖长时站立验证。
