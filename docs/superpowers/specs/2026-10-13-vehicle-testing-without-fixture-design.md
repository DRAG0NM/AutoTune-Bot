# 无测试支架实车测试设计

日期：2026-10-13
状态：待项目负责人审阅
适用对象：AutoTune-Bot + AutoTune-HC04 实车；由操作者与 DSH 执行，测试数据经独立审核后同步入项目证据库。

## 目标与边界

在不使用测试支架的条件下，逐步建立本车自主平衡表现的可复现证据，并用 DSH 后续记录更新测试安排。第一目标是查明现有短时松手表现能否复现，以及终止原因；不是立即搜索“最佳 PID”。

本设计允许在地面做受保护的短时松手测试，前提是每轮都有一名专职观察员、清空并标记测试区域、可立即触达的电池断电手段，且车轮周围无人接触。任何一项不满足，动态松手阶段暂停，只做静态、协议和不声称自主平衡的手扶观察。K1 保留为控制停机；物理断电是通信/控制停机不确定时的最终手段。

测试期间使用同一辆车、单一串口控制端和单一操作者。禁止在测试区域内同时操作手机端、串口助手或第二主机。测试记录不指导公开场地运行，也不把仿真最优参数直接用于实车。

## 证据审查基线

| 记录 | 当前可支持的结论 | 不能据此声称 |
|---|---|---|
| E4 看门狗 | 固定车体时，停止心跳后约 508 ms 观察到 `fault=1` 且输出为零 | 所有姿态/链路下的停机时间都相同 |
| E5 K1 | K1 后读到 `fault=6` 和 PWM=0 | 2531 ms 是 K1 电气响应时间；该数含操作者反应和轮询间隔 |
| E6 运行中拒写 | 两次确认运行态后，写参得到 `E,busy`，读回未改变 | E2 有效；E2 写参前已被 tilt 停机 |
| B4-10s-run3 | 唯一一条事后识别为松手的短时观察；配置请求为 Angle 5/0/5、速度环冻结、Offset=-0.48 | 可重复的 3 秒稳定能力或 Offset=-0.48 已生效 |
| 其它 G2/G3 落地 CSV | 在更正稿中归类为手扶，可分析特定配置下的控制律行为 | 自主平衡能力、最稳参数或可比较的单次 J |

B4 配套记录中的静态角样本为 -14.56° 至 +8.30°，均值 -0.48°；此窗口不满足稳定配平的证据要求。固件接受的 Offset 范围为 0–30，负值写入会被拒绝，故新测试不得把请求值当成实际值。CSV 有 36 个样本、覆盖 3500 ms；其中角度在 ±1.3° 内的连续样本跨度为 1900 ms。记录没有松手时刻、同期操作者状态或明确的停机事件时间线，最终状态报告 `fault=2`。因此本轮是探索线索，不是性能验收结果。

其它风险信号：手扶基线 E3 约 400 ms 即 tilt 停机；部分记录出现 `target=-20`、`out=-100`、`errInt=-600` 的级联饱和；10 秒请求的另一轮运行记录约 10.47 秒，存在约 4.7% 正偏差。试验时长以设备 tick 和停机事件计算，不能只看主机请求值。

## 测试阶段与放行门

### V0：会话与设备身份

每个测试批次分配唯一 `campaignId`，每次启动分配唯一 `runId`。开始前记录板卡/车辆标识、电池电压、地面、轮胎与机械检查、固件版本、烧录 HEX SHA-256、烧录时间、主机 Git commit 与工作区差异、DSH 探针版本/散列、串口通道、日期时间及操作者/观察员角色。无法确认现场 HEX 身份时，不进入候选参数比较；记录仍可作为未绑定构建身份的观察材料。

### V1：静态检查、状态与参数核验

电机不运行时完成只读检查，确认版本、`running=false`、PWM=0、无未解释故障，读取十项参数。记录直立静态角和至少 5 秒的连续遥测窗口，并明确车体是否被触碰。项目现有直立读数 ±1° 可作为初始核对线；若窗口持续漂移、样本明显受手扶/摆放过程影响或角度方向不确定，则先排查机械/传感器，不配平、不 Start。

参数应用必须 fail-closed：先 Stop，写入预注册配置，逐项读回全部十项并与目标值逐项比较。任何写入拒绝、超时、缺项或不相等都使该轮标记 `invalid-config`，禁止 Start。测试后再次读回，记录恢复动作和最终状态；不得仅因脚本发出了 slider 帧就记为已应用。

### V2：短时安全筛查

观察员确认隔离区和物理断电可用后，先做不超过 2 秒的单轮筛查；该轮仅判断启动、方向趋势、遥测和停机链路，不用于性能排名。DSH 必须在运行中监视遥测；下列任一情况出现即触发停止：角度绝对值达到 15°、连续两帧 `abs(out) >= 80`、设备/主机遥测间隔超过 300 ms、车辆越出标记区域、出现异响/碰撞/异常运动，或观察员判断控制已不可靠。优先使用已验证的 K1/Stop；无法立即确认 `running=false`、PWM=0 时直接物理断电。触发安全停止的轮次保留数据并标为失败/中止，不自动重启。

15° 和输出阈值是本设计的保守现场中止线，不是平衡成功标准；试验前由操作者和观察员确认可执行。固件 ±50° tilt 是最后保护，不可作为现场允许达到的角度。

### V3：候选基线复现

只有 V0–V2 全部通过，且筛查轮无安全中止、无配置/链路问题时，才进入基线复现。首个候选按历史记录的请求条件登记为 Angle 5/0/5、Speed 0/0/0、Offset 3；这只是待验证候选，不是已认证参数。该值必须由本轮设备读回证实。Offset 设为 3 是为明确取代先前被拒绝的 -0.48 请求，不表示 3 已被证明最优。

一次只执行一轮；起始角和电池/地面条件满足本轮预注册要求，操作者在日志中记录实际松手的设备 tick/主机时间，之后不接触车体。首轮最多运行 3 秒。审核原始曲线和终态后，若无中止、读回匹配、停止原因可解释，才允许延长到当前主机工具支持的 4 秒上限。超过 4 秒的长时测试必须先有经验证的独立时限保护和停止延迟记录；不得用无限时 `start` 代替限时试验。

基线达到目标时长且安全停止后，最多重复三次以检查重复性；每轮之间重新检查姿态、故障、参数、机械状态和电池情况。任何一次配置不符、状态未知或异常中止，暂停重复和参数变化，先审核该轮。

### V4：一次一个变量

只有基线至少三轮的配置和证据有效，且结果差异已解释或量化，才开始对照。每个新条件只改变一个因素，按“基线—单变量候选—基线复测”的顺序安排，速度环、转向环、Offset、固件和场地条件不能同时变化。Offset 负值能力属于固件/协议变更，应另立固件验证批次；变更前后必须区分构建身份，不能与增益搜索合并成同一 campaign。

若活动目标是提高自主平衡时长，候选评价至少报告松手后有效时长、角度峰值/RMS/预定角度带内占比、角速度趋势（若可采）、左右轮速、输出饱和占比、漂移方向、停止原因及重复次数。目标角度带和达标门槛必须在查看候选结果前写入 campaign。速度环启用且 `target` 变化时不计算现有恒定 target 的 J；即使速度环冻结，也先保留指标向量，不把未经验证的单一分数称为“最优”。

## 每轮数据契约

DSH 在临时验证目录中新增不可覆盖的原始文件，另写机器可读 JSONL 事件索引。每轮至少记录：

- `campaignId`、`runId`、测试阶段、假设、单一变量、预注册目标时长、操作者/观察员角色。
- 车体状态：`held`、`released` 或 `no-motor`；松手/重新接触时刻及证据文件引用。事后补录必须带 `postHoc: true`，不得冒充同期记录。
- 设备身份和固件/主机/探针散列；起始/结束电池电压、地面、静态角窗口及测试区域条件。
- 十项参数的目标值、写入回执、每项读回值、起始/结束状态；配置核验布尔值及失败原因。
- `start`/心跳/Stop/K1/断电等关键事件的主机时间、设备 tick、原始回执；请求时长、实际运行时长、最后遥测 tick、终态 fault/running/PWM、明确停止来源。
- 原始 JSONL 和 CSV；视频或观察记录引用；探针诊断和审核状态。不得仅保存汇总值。

探针须修正当前已知缺口：写参未生效时不能继续 Start；运行期间要保留安全阈值触发记录；结束时读取 Status 和全部参数；把操作者状态、松手 tick 和停止来源写入 JSONL；超时或断链要明确区分 `unknown-stop`，不能推断成正常结束。长运行时主机计时和设备 tick 同时记录。

## DSH 执行与项目同步

1. DSH 先读取本设计及 `docs/vehicle-commissioning.md`、`evidence/07_vehicle/20261013/README.md`，再在 `DSH临时实车验证` 新建批次目录和 manifest；DSH 对项目主目录只读。
2. 操作者逐阶段授权并执行。每次 Start 前 DSH 口头/文本复述目标配置、限制时长和断电条件；操作者确认设备已就绪后才启动。DSH 不自动跨越阶段、不自动重试 Start、不在异常后自动恢复运行。
3. 每轮结束后 DSH 输出原始文件引用、运行摘要、无效性/安全事件和待解释项。先由独立审核者检查原始帧、参数读回、时间戳、CSV 复算、操作者状态和停止原因。
4. 审核通过的原始文件按原字节复制到 `evidence/07_vehicle/<日期或campaignId>/data/`；审核说明和测试状态另存，不回写源记录。校验 SHA-256，并更新证据 README 和项目实验状态。审核不通过的数据仍保存在临时原始区，项目只记录其无效原因，不据此选择参数。
5. 每轮审核后再决定继续、重复、改变一个变量或暂停。没有自动寻优；每个参数变化都要求操作者明确确认。

## 中止与重新进入

发生摔倒、硬件松脱、电池/驱动异常、意外接触、通信中断、状态读回未知或安全阈值触发：立刻停止，不做同轮重试；断电并检查机械、电源、参数和故障原因。清除非计时 fault 前确认车体已扶正并静止，再发 Stop 并读回；`fault=4` 按固件计时故障流程复位并排查。修复后新建 `runId`，保留失败记录，重新从对应阶段门进入。

## 本设计的退出条件

- 可绑定到明确硬件和构建身份的有效松手记录达到预定重复数。
- 失败、中止、配置错误和正常停机均有可区分的事件时间线。
- 评价口径在测试前固定，且不使用不适用的恒定 target `J`。
- 独立审核者能够仅凭归档文件复算本批结论，并追溯每轮参数及原始数据。

达到以上条件表示测试批次可审查、候选可比较；不自动等价于产品级安全认证或长期可靠性结论。
